# Baosky 中的 AI 可扩展性

本文概述了 Baosky 中的 AI 可扩展性选项，帮助你为插件选择正确的方法。

Baosky 包含强大的 AI 功能，可增强编码体验：

- ** 代码补全 ** ：在你输入时提供内联代码建议
- ** Agent 模式 ** ：使 AI 能够使用专用工具自主规划和执行开发任务
- ** 聊天 ** ：让开发者通过聊天界面使用自然语言提问或在代码库中进行编辑
- ** 智能操作 ** ：使用 AI 增强的操作来处理常见开发任务，集成在整个编辑器中

你可以扩展和自定义这些内置功能，创建满足用户特定需求的定制 AI 体验。

## 为什么要在 Baosky 中扩展 AI？

为插件添加 AI 功能可为用户带来多项好处：

- ** Agent 模式中的领域特定知识 ** ：让 Agent 模式访问你公司的数据源和服务
- ** 增强用户体验 ** ：提供针对插件领域定制的智能辅助
- ** 领域专业化 ** ：创建特定于编程语言、框架或领域的 AI 功能
- ** 扩展聊天功能 ** ：向聊天界面添加专用工具或助手，实现更强大的交互
- ** 提高开发者生产力 ** ：使用 AI 功能增强常见的开发任务，如调试、代码审查或测试

## 扩展聊天体验

### 语言模型工具

语言模型工具使你能够通过领域特定功能扩展 Baosky 中的 Agent 模式。在 Agent 模式下，这些工具会根据用户的聊天提示自动调用，以执行专门任务或从数据源或服务检索信息。用户还可以通过在聊天提示中使用 # 提及工具来显式引用这些工具。

要实现语言模型工具，请在 Baosky 插件中使用 [Language Model Tools API](/api/插件-guides/ai/tools)。语言模型工具可以访问所有 Baosky 插件 API，并提供与编辑器的深度集成。

** 主要优势 ** ：

- 作为自主编码工作流程一部分的领域特定功能
- 你的工具实现可以使用 Baosky API，因为它在插件宿主进程中运行
- 通过 Visual Studio 市场 分发轻松和部署

** 主要考虑因素 ** ：

- 远程部署需要插件实现客户端-服务器通信
- 跨不同工具的重用需要模块化设计和实现

### MCP 工具

模型上下文协议 (MCP) 工具提供了一种通过使用标准化协议将外部服务与语言模型集成的方法。在 Agent 模式下，这些工具会根据用户的聊天提示自动调用，以执行专门任务或从外部数据源检索信息。

MCP 工具在 Baosky 之外运行，可以在用户的机器上本地运行，也可以作为远程服务运行。用户可以通过 JSON 配置添加 MCP 工具，或者 Baosky 插件可以以编程方式配置它们。你可以通过各种语言 SDK 和部署选项实现 MCP 工具。

由于 MCP 工具在 Baosky 之外运行，因此它们无法访问 Baosky 插件 API。

** 主要优势 ** ：

- 添加领域特定功能作为自主编码工作流程的一部分
- 本地和远程部署选项
- 在其他 MCP 客户端中重用 MCP 服务器

** 主要考虑因素 ** ：

- 无法访问 Baosky 插件 API
- 分发和部署需要用户设置 MCP 服务器

### 聊天参与者

聊天参与者是专门的助手，使用户能够通过领域特定专家扩展询问模式。在聊天中，用户可以通过 @ 提及聊天参与者并传入有关特定主题或领域的自然语言提示来调用它。聊天参与者负责处理整个聊天交互。

要实现聊天参与者，请在 Baosky 插件中使用 [Chat API](/api/插件-guides/ai/chat)。聊天参与者可以访问所有 Baosky 插件 API，并提供与编辑器的深度集成。

** 主要优势 ** ：

- 控制端到端交互流程
- 在插件宿主进程中运行允许访问 Baosky 插件 API
- 通过 Visual Studio 市场 分发轻松和部署

** 主要考虑因素 ** ：

- 远程部署需要插件实现客户端-服务器通信
- 跨不同工具的重用需要模块化设计和实现

## 构建自己的 AI 驱动功能

Baosky 为你提供对 AI 模型的直接编程访问，用于在插件中创建自定义 AI 驱动功能。这种方法使你能够构建使用 AI 功能的编辑器特定交互，而无需依赖聊天界面。

要直接使用语言模型，请在 Baosky 插件中使用 [Language Model API](/api/插件-guides/ai/language-model)。你可以将这些 AI 功能集成到任何插件特性中，例如代码操作、悬停提供程序、自定义视图等。

** 主要优势 ** ：

- 将 AI 功能集成到现有插件功能中或构建新功能
- 在插件宿主进程中运行允许访问 Baosky 插件 API
- 通过 Visual Studio 市场 分发轻松和部署

** 主要考虑因素 ** ：

- 跨不同体验的重用需要模块化设计和实现

## 决定使用哪个选项

在为 Baosky 插件选择扩展 AI 的正确方法时，请考虑以下指南：

1. ** 选择语言模型工具的情况 ** ：
    - 你想用专门功能扩展 Baosky 中的聊天
    - 你想在 Agent 模式下基于用户意图自动调用
    - 你想访问 Baosky API 以在 Baosky 中进行深度集成
    - 你想通过 Baosky Marketplace 分发你的工具

1. ** 选择 MCP 工具的情况 ** ：
    - 你想用专门功能扩展 Baosky 中的聊天
    - 你想在 Agent 模式下基于用户意图自动调用
    - 你不需要与 Baosky API 集成
    - 你的工具需要在不同环境中工作（不仅仅是 Baosky）
    - 你的工具应该远程或本地运行

1. ** 选择聊天参与者的情况 ** ：
    - 你想用具有领域专业知识的专门助手扩展询问模式
    - 你需要自定义整个交互流程和响应行为
    - 你想访问 Baosky API 以在 Baosky 中进行深度集成
    - 你想通过 Baosky Marketplace 分发你的工具

1. ** 选择语言模型 API 的情况 ** ：
    - 你想将 AI 功能集成到现有插件功能中
    - 你正在构建聊天界面之外的 UI 体验
    - 你需要对 AI 模型请求进行直接编程控制
